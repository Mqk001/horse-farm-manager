# HTML rendering audit

Scope: application source (`src`, 83 files), tracked configuration, dependencies declared in package.json, and tests. Vendor/framework internals and generated build output are outside the application-source findings below.

## Framework and DOM bypasses

No occurrences of `dangerouslySetInnerHTML`, `__html`, `v-html`, Angular trust bypasses, `innerHTML`, `outerHTML`, `insertAdjacentHTML`, document writing, contextual HTML fragments, DOMParser, iframe `srcDoc`, unsafe HTML/SVG directives, or raw Markdown plugins were found. No HTML parser/sanitizer or Markdown rendering package is declared. Application text, including names, notes, task titles, and error messages, uses ordinary React rendering with automatic escaping. No framework bypass needed removal or sanitization.

## HTML email generation

Email templates generate HTML strings outside React, so their substitutions were also reviewed. Every template is in `src/lib/email.ts`.

| Template | Input and existing safety | Handling |
| --- | --- | --- |
| Verification email | User name already HTML-escaped. Verification URL generated from a parsed request URL origin and an encoded server-generated token in signup/resend-verification routes. No arbitrary submitted HTML is rendered. | Escape the URL in the quoted href attribute as well, for consistent defense in depth. |
| Farm invitation | Farm name and role already HTML-escaped. Invitation URL generated from a parsed request URL origin and encoded server-generated token in the invitations API. | Escape the URL in the quoted href attribute as well. |
| Password reset | Name and reset URL already HTML-escaped. Link generated by the password-reset route from a checked origin and server-generated token. | Safe for HTML interpolation; retained. |

These are fixed templates containing text, not a feature accepting rich HTML. Escaping is appropriate; adding a rich-HTML sanitizer would be unnecessary. Attribute escaping prevents markup injection, but is not URL protocol validation. Current callers construct HTTP(S) application links; accepting arbitrary future links would require separate URL validation.

No exploitable raw-HTML UI bypass was identified. The two link-escaping changes harden email generation rather than establish that a current caller was exploitable.
